# Kalshi Bitcoin 15-minute advisor

## Speed audit · October 23, 2026

On battery, Windows ran the engine 3.5–7× slower than normal and the Kalshi book fell seconds behind in busy minutes (independent connections on the same PC stayed current). The engine, web server and markets process now opt out of Windows power throttling at startup, the guardrails no longer re-date every past trade 4× a second, and the Coinbase order-flow recorder is off by default. Feeds & latency shows how busy the engine loop is; a busy engine is named as the cause of a delay. See DECISIONS 65.

## Order flow and execution research · October 23, 2026

An independent Coinbase BTC-USD recorder (off by default since the speed audit below; set RECORD_ORDER_FLOW=on in .env.local) captures public trades, batched L2 updates, heartbeats, source/arrival timestamps, depth imbalance, microprice and 30-second order flow. New final-minute checkpoints freeze a small BRTI calibration challenger alongside the current quant and market probabilities. These research features and forecasts do not change trading advice or place orders.

Calibration shows prospective paired probability scores and automatic depth-based execution replay. `npm run execution:study` writes the full read-only report to `output/EXECUTION-STUDY.md` and `.json`; add `-- --through <ISO-time>` for a fixed cutoff. Replay uses frozen fee-aware limits, latency scenarios, partial fills and actual recorded depth, and explicitly excludes missing or stale data. See [the research protocol, formulas, limitations and news-data plan](docs/RESEARCH-ENGINE-2026-10-23.md).

## Quantitative engine update · October 23, 2026

The main learner now uses expanding chronological validation: a training outcome must have been observed before the test block, with an additional 60-second embargo. Each settled market contributes one unit of training weight, regardless of its snapshot count. Adoption requires at least 60 later markets, 20 hourly blocks, stable gains across periods, positive block confidence bounds versus both the default blend and usable market odds, and no worse log loss. Legacy mixed-time scores are labelled separately on Calibration.

The app also receives the **official CF Benchmarks BRTI** through Kalshi's authenticated 1 Hz and 5 Hz channels. Its independent connection records source and receive timestamps. The new **Official BRTI** panel shows price, freshness, and a separate settlement forecast using exact discrete Brownian covariance for the 60 one-second settlement observations. Missing official seconds, stale data, or an unconfirmed strike suppress that forecast. Five-Hz updates are never counted as five settlement observations. No new subscription or paid service was purchased.

The BRTI forecast is a **forward experiment**: its fixed-horizon forecasts are immutable and scored beside the proxy, current quant forecast and market in Calibration. It does not drive entries, sizing, exits or orders. Reference ticks retain 30 days at 1 Hz and seven days at 5 Hz; checkpoint forecasts are retained permanently. Existing evidence and risk settings still apply.

- `npm run quant:research -- --through 2026-10-23T07:20:00Z`: reproducible read-only audit of recorded decisions, chronological holdout, paired probability scores, and ask/fee/slippage diagnostics. [Results](docs/QUANT-RESEARCH-2026-10-23.md).
- `npm run benchmark:study`: download/cache official history using existing Kalshi credentials and replay the fixed BRTI formula; add `-- --skip-fetch` to reuse `data/benchmark-history.db`. [All horizon results and limitations](docs/BRTI-STUDY-2026-10-23.md).
- [Formulas, sources and verification](docs/QUANT-ENGINE-2026-10-23.md).

The recorded evidence supports better validation and an improved source for further research. It does not yet establish a reliable profit advantage over Kalshi after costs.

Local, read-only research and trading discipline dashboard for KXBTC15M. It does not send orders. No hosting or paid feed is required. A median of four public spot venues approximates BRTI; it is not the official index. Fair value is an uncalibrated diffusion estimate. The journal is designed to measure whether that estimate has an edge.

## Setup

Requires Node.js 22.12+ (tested with 24), npm, and a Kalshi API key (Ed25519 or RSA PEM saved under keys/). Windows needs network access for the better-sqlite3 prebuilt binary; if unavailable, npm needs local C++ build tools.

```powershell
npm install
# If .env.local does not exist, copy .env.example to .env.local.
# Put the private PEM under keys/ and enter the key ID and path in .env.local.
# Set DASHBOARD_USER and a strong DASHBOARD_PASSWORD.
npm run check
npm run dev:all
# Or for the tested production launcher:
npm run trade
```

Open http://localhost:3000 and use the credentials from .env.local. Engine binds 127.0.0.1:3001; dashboard binds 127.0.0.1:3000. Basic auth is enforced before every HTTP request and WebSocket upgrade, unless `DASHBOARD_AUTH=off`: then requests made on this PC skip it. A request counts as local only if it arrives on loopback, is addressed to localhost/127.0.0.1/[::1] (which refuses DNS-rebinding hostnames) and has no X-Forwarded-For / Forwarded / Tailscale-* headers. Tailscale and phone access still use the password. Use the custom launcher, not `next start`, which bypasses that wrapper. Do not forward raw HTTP outside this computer; [phone setup](docs/PHONE.md) uses Tailscale HTTPS.

`.env.example` contains all environment variables. Credentials are server-only and requests carrying signatures go exclusively to fixed official Kalshi hosts; redirects fail. Public venue connections receive no credentials. v1 refuses `ENABLE_EXECUTOR=true`. `Executor` defines the future integration boundary, but this version has no API write method. keys/, .env.local and SQLite files are Git-ignored.

`npm run trade` runs tests, TypeScript validation and the production build, requests an OS wake lock, then supervises engine and web. Crashes restart with bounded backoff. Ctrl+C stops it. Startup failures stop launch. Logs are in logs/ and the events table. Do not run trade and dev:all simultaneously on the same ports.

## Architecture

```text
Coinbase / Kraken / Bitstamp / Gemini public WS
                  | quote age filter → median → 1s history
Kalshi read-only REST + signed WS → local sequenced orderbooks
                  |
     tsx engine → volatility → average moments → fair probability
                  |           → fee-aware taker/maker → guardrails
                  +→ SQLite journal / paper fills / outcomes / calibration
                  |
              authenticated loopback WS (3001)
                  |
       authenticated custom Next.js server (3000)
                  |
      desktop browser / Tailscale HTTPS → phone
```

Files: `src/engine/feeds/` owns reconnecting sockets, quote median, signing, REST, and books. `model/` holds pure volatility, conditional-average math and fee functions. `signals.ts` holds gates and Kelly sizing; `guardrails.ts` holds discipline; `account.ts` ingests real records; `journal.ts` owns SQLite; `calibration.ts` computes metrics. `src/app/` contains App Router pages; `src/components/` contains charts, settings and shadcn-style primitives. `src/markets/` is the separate markets process (port 3002, `data/markets.db`) behind the Markets page. `scripts/web.ts` authenticates and bridges both processes (`/ws`, `/api/engine/*` and `/markets-ws`, `/api/markets/*`); `scripts/trade.mjs` supervises; `tests/` contains pure and journal tests. [Verified API notes](docs/kalshi-notes.md) and [decisions](DECISIONS.md) explain current protocol differences and assumptions.

## Reading the dashboard

- **Price action is always visible** at the top, beside a compact trade decision on desktop and before it on phones. Switch Bitcoin / Kalshi YES and candle intervals; **Latest** returns to current prices. History refreshes preserve live candle extremes and your zoom, and updates pause when the engine state is stale. Failed or waiting trade checks stay visible; expand **View all** for the full checklist.
- **Section help:** hover or focus any circled **i** for an explanation. Click to pin it open (also works on touch); press Escape or click outside to dismiss. Help covers the instrument strip, entry decision and checks, forecasts, positions, charts, book, session, feeds and settings.
- **BTC · next move** below the candle chart estimates Bitcoin proxy direction at 30 s, 1 min and 3 min. Selecting a horizon draws a dashed future estimate and shaded nominal 80% range on the Bitcoin chart. It uses closed-candle features, momentum and volatility, requires five uninterrupted minutes and at least three healthy venues, and pauses with stale data. It begins in **Learning / UNCLEAR (50–50)**; learned calls activate only after chronological tests pass a grouped confidence check. **Measured results** separates candidate later-data validation from immutable live forecasts scored at their original deadlines. Missing endpoints and flat prices are disclosed, not counted as wins. CSV export is available there. This forecast does not drive settlement entries, position sizing, exits or sounds. See [short-term forecast design and verification](docs/SHORT-TERM-FORECAST.md).
- The engine evaluates and pushes state 4× per second on live quotes; ticks and signals are journaled once per second. Kalshi and exchange feeds are push WebSockets, so on-screen data is typically under ~300 ms old plus browser render time.
- Countdown is seconds to contractual close, corrected against Kalshi server Date. At close it rolls automatically. Opening **K ✓** comes from floor_strike; **estimated** means a complete proxy opening-minute average. Missing K blocks the model.
- Proxy is the median of live venues. A venue is live while its WebSocket answers within 2 s (pinged every second) and its last quote is under 15 s old — venues push quotes only when prices change, so a quiet quote on a live link is valid. A green dot means a connected venue with a fresh quote. Quote age and transport lag are different; lag is unavailable when a source has no exchange timestamp.
- Distance is current proxy minus K in dollars. Sigma units are standardized expected-average distance in log space. Sigma is volatility per square-root-second, not annual volatility. The regime percentile compares recent rolling estimates and begins with limited history.
- Model UP is the probability the closing average clears K, clipped 1–99%. It blends EWMA and one-hour return variance. Warm-up requires 120 contiguous one-second returns. In the final minute, observed proxy seconds contribute to the conditional average; missing seconds suppress it. The locked counter is proxy coverage, not confirmed BRTI.
- Net YES/NO edge subtracts the ask and one-contract taker fee from the corresponding probability. BUY appears only after all configured gates pass. The reason explains a failed gate or the model/ask/fee comparison.
- Suggested contracts use quarter Kelly, capped at 2% of cash balance and 25 contracts. Spend and maximum loss include the fee rounded on the whole proposed order. No authenticated balance means zero sized suggestions and no taker entries. Existing position exposure is shown in the account data but the v1 size cap is per trade, not a full portfolio risk optimizer.
- **Backtest beside every BUY**: each BUY signal (15-minute and hourly) shows how the same rule did in `npm run backtest`, per contract after fees with its likely range, and says *no proven edge* when that range includes zero. The engine reloads `data/backtest-verdict.json` whenever the backtest is re-run; results older than two weeks say so. With *Use quant forecast for signals* off, the raw model's result is quoted instead.
- **Your positions · exit plan** (default *hold* mode since the backtest: keep to settlement, because early exits did worse than holding the same entries). Hold mode shows one steady HOLD until SETTLING, coloured by your live P&L (UP/DOWN in dollars and %), with the best and worst gain so far and the win chance now versus when you bought. A heads-up box and sound call out big moves while the plan stays HOLD: a gain past the ride level (+25%, or half the maximum possible gain for expensive contracts), giving back half of such a gain, a loss past the cut-loss level (−50%), or the win chance falling 25 points since entry. Each shows what selling now would lock in or lose. Notices stay on until clearly cleared (80% of the threshold), and each is logged (`exit-notice`). Cost per contract includes the entry fees you actually paid (FIFO over your open fills; estimated from Kalshi's exposure while a sync is in flight, labelled), so *P&L if sold* includes both fees. Positions refresh on every fill and every 30 s, and the box shows when they were last synced. *Risk* mode: HOLD until +25%, then **RIDE** with a trailing take-profit (TAKE PROFIT once the gain gives back half of its peak, never below +5%); stops as before. Earlier fixed version: TAKE PROFIT when selling locks in ≥ 25%, CUT LOSS when selling loses ≥ 50% or the forecast win chance drops below 25% (while a bid ≥ 5¢ remains), LET IT SETTLE above a 97¢ bid, TOO LATE when there is nothing worth selling, otherwise HOLD with the exact trigger bids shown. Exits are sticky (stay up until the position clearly leaves the zone), have their own repeating sounds, and every change is logged (`exit-advice` events). *EV* mode keeps the original pure expected-value comparison below.
- Original EV comparison: values each open KXBTC15M position (Kalshi `position_fp`: positive = YES, negative = NO) two ways: *hold* = contracts × model P(your side wins), settling at $1 with no exit fee; *sell now* = contracts × your side's best bid − taker fee. It says SELL NOW only when selling beats holding by at least `exitMargin` (default 2¢/contract), otherwise HOLD, and suggests a resting sell at fair value + maker margin as a middle path. Positions in markets without a ready model show NO MODEL. It maximizes expected value under an uncalibrated model; it cannot guarantee the most profitable exit.
- **Sound alerts** (on by default on the 15-minute and hourly pages; speaker icon in each header; full panel under *Sound alerts*; saved prefs from before this default were switched back on once). On */hourly* the sounds follow the hour: its best BUY, hourly exits, the up/down call, 15:00 and final-minute timing, plus lock and data warnings. distinct synthesized sounds for BUY YES / BUY NO, SELL NOW on your position (repeats every 15 s while it lasts), HOLD (new position or back from sell), win / loss (realized P&L today rises / falls), live-call flips, new window, entry window (5:00 left), final minute, data unreliable / connection lost (max once per 30 s) and guardrail lock. Per-category toggles, volume and Test buttons; saved per browser. Browsers require one click on the page before audio can play.
- **Desktop shortcut**: `npm run shortcut` creates *Kalshi Advisor* on the desktop. It starts the app in a minimized window (close it to stop) if it is not already running or starting, waits for it, then opens http://localhost:3000 in a dedicated Chrome profile (`%LOCALAPPDATA%\KalshiAdvisor\Chrome`) started with autoplay allowed, so sound alerts play without a first click. Log in once in that window. Opened in any other browser, the page still needs one click before it can play sound.
- **Hourly page** (`/hourly`, Kalshi **KXBTCD**): each hour has a ladder of strikes $100 apart; a strike pays YES if the 60-s BRTI average before the top of the hour (ET) is above it — the same settlement mechanics as the 15-minute markets, so the same model prices every strike. Shows the hour's up/down call versus the proxy average of the 60 s before the hour opened (Kalshi's view interpolated from the ladder), the best trade after fees with the same gates as the 15-minute signal, the live strike ladder, exit plans for hourly positions, and past hours with calls frozen at 45/30/15/5/1 min scored against results. Prices are read by REST every 3 s.
- **Recent rounds** (dashboard): the last 16 windows with the opening, 5:00 and 1:00 calls, the next-window preview, the result and your P&L, plus rolling 10-round hit-rate sparklines and all-time Brier per call type.
- **Volatility is horizon-scaled**: 1-s volatility × √(variance ratio). The ratio (prior 1.5, updated from the last hour's 60-s returns) corrects the median-proxy's second-to-second smoothness; it is shown in Feeds & latency.
- **Quant engine** (`src/engine/quant/`): the forecast used for calls, signals and hold/sell is a Bayesian logistic blend of the diffusion model, the Kalshi midpoint and momentum/flow features: `logit q = b + a·logit(model) + c·(logit(Kalshi) − logit(model)) + Σβ·features`. With no evidence it is a logit blend weighted 90% toward the market with zero feature weight; it is refit after every settled window and the learned weights are adopted only when they beat both the default and market baselines in purged chronological tests with positive block confidence bounds. Turn *Use quant forecast for signals* off to trade on the raw model. The proxy→BRTI basis (recent median settlement residual) is learned automatically from settlements (*Auto basis*).
- **Next window** previews the following 15-minute window. Its opening price K is this window's settlement average, so during the final minute the head start `S_close − A` becomes partly known; before that the preview is ≈ 50% plus learned momentum effects. Snapshots at 1:00 and 0:10 before it opens are scored.
- **Scalp & dip** (priced after fees): *scalp* = buy a side the market sells well below fair value and rest a sell at a target halfway to fair (≥ 2¢ above entry), with a bail level; *dip* = a side's ask fell ≥ 8¢ in a minute while fair value did not (overreaction → buy, target the half retrace) versus a drop the model agrees with (*falling knife*). Every setup is paper-traded: target fill if the bid reached it before close, otherwise held to settlement.
- **Markets page** (`/markets`, stage 1 of [the markets spec](docs/superpowers/specs/2026-10-09-markets-advisor-design.md)): every open Kalshi position outside KXBTC15M/KXBTCD (sports, combos, politics and economics, commodities and other crypto), filterable by category. A separate `markets` process supervised by the launcher feeds it, so the Bitcoin engine never waits on it.
  - **Cost** per contract includes the entry fees you paid: FIFO over your open fills, or exposure + fees paid until those sync (labelled *estimated*).
  - **P&L if sold** is at the bid after the taker fee. **Value if held** is at market odds (YES mid × $1).
  - **Verdict:** HOLD, or SELL BEATS HOLD only when the bid nets more than the position is worth by max(0.05¢, min(`exitMargin`, 20% of the win chance)). With Kalshi's odds alone it nearly always says HOLD; outside prices come in stage 3.
  - **Combos** list every leg (won / lost / to play, bid/ask, chance) and are valued as the product of the legs. That assumes independent legs, so legs on the same game are flagged *rough*. A lost leg shows DEAD; a missing leg leaves the value unavailable. The headline compares that value with the cost (*at leg odds*), because a combo's own bid sits on an almost empty book.
  - **Heads-ups** follow the Bitcoin hold-mode rules (big gain, give-back, −50%, odds down 25 points), plus *leg won*, *one leg left* and *combo dead*. They have their own sounds in the *Other markets* category and play on every page, but only one open tab plays each.
  - **Refresh:** quotes every 5 s (≤ 5 Kalshi requests/s); prices saved every 30 s for the price line. A card greys out when its prices are over 30 s old.
  - Exit settings are read from the dashboard Settings.

  - **How accurate Kalshi's prices were.** Settled public markets grouped by their YES price 24 h or 1 h before the result was due (Kalshi's `occurrence_datetime`, else settlement), or averaged over those 24 h weighted by volume. For team sports the occurrence time is about the end of the game, so 24 h is the pre-game line and 1 h is usually in play. Each price band shows how often it won (Wilson 95% range) and what buying YES at the ask returned per $1 after the taker fee (bootstrap 95% range over whole events, so both sides of a game count once). A reliability chart sits above the table.
  - **Coverage.** The top 20 series by lifetime volume in each of sports, politics & economics, and commodities & crypto, plus every series you have traded. Each series is sampled evenly by ticker hash (at most 4,000 per series per run) without regard to volume or result. A market counts at a horizon only if it had a two-sided book then. Combos never trade publicly, so they appear only in your record.
  - **Data.** `npm run markets-backfill` (public data, ≤ 5 requests/s, resumable, into `data/markets.db`) covers everything since Kalshi's archive cutoff. The markets process re-runs it daily at low priority, 10 minutes after start at the earliest, never beside a run already going (heartbeat). The accuracy tables are computed by that run, not by the markets process.

  - **Polymarket** (public, no key) for team-sports moneylines, full-game totals at exactly the same line, and politics and other events.
  - **Sportsbook consensus** from The Odds API when `ODDS_API_KEY` is in `.env.local`. It covers moneyline and totals, the median across books with each book's margin removed. To stay inside the free ~500 requests a month it only fetches leagues you hold (every 30 min when a held game is near, else every 6 h) and stops below 50 requests left.

  **Sports matching is automatic:** league, a game time within [Kalshi's expected time − 8 h, + 6 h], and both teams pairing uniquely by code, name word or initials. Anything ambiguous, including doubleheaders, is left unmatched.

  **Other markets get a Polymarket title suggestion.** It is shown in grey with ✓ Same market / ✗ Not it. A rejection is permanent.

  **Trusted references** are auto-matched sports or ones you confirmed, fresh (Polymarket ≤ 15 min, sportsbooks ≤ 2 h), with a book ≤ 10¢ wide. They become the win chance for hold value and the hold-or-sell verdict, and the card still shows Kalshi's next to them. Combos are valued leg by leg at outside odds where available ("Outside" column).

  **Refresh:** Polymarket every 5 min, every minute while a held game is in play.

  **Scoring:** reference prices are snapshotted every 5 min. Once matched markets settle, Record compares Kalshi's and the outside Brier scores (shown from 10 markets).

  A source strip on Positions shows each source's state.

It keeps those with ≥ $1,000 traded in 24 h, plus anything you hold (about 320 markets), snapshots them, and matches the sports ones to Polymarket. Three kinds of flag, each a one-contract paper trade (at the flagged side's ask plus the taker fee) scored when the market settles:

  - **1-hour move:** the YES mid moved ≥ 10¢ in an hour on ≥ $500 traded, not matched by the outside price. Stored as follow and fade. Not for commodities and crypto.

- **Timing** shows a clock (*waiting*, with a countdown) before the entry window and during the final minute: that is the schedule, not a fault, and it is not counted as a failing check.
- **Trade checks** list every gate behind BUY / NO TRADE (market, feeds, book, K, model, account, guardrails, edge, timing, spread, depth, size) with the observed value; failing ones are amber. A test guarantees the checklist agrees with the decision.
- **Live call** re-runs the opening-call formula on current data ~3×/s. Direction only flips once P(up) clears 50% by 2 points, so it does not flicker; *held* and *flips* show its stability. It pauses when data is unreliable (model warming, fewer than 2 live price feeds, or estimated K) and shows a DEGRADED badge for softer issues (a feed down, Kalshi REST fallback, stale book, clock unsynced). Snapshots at 10:00, 5:00, 2:00 and 1:00 left are journaled (`live_calls`) and scored per horizon on the Calibration page; late horizons naturally look accurate because the outcome is mostly decided, so compare them with the Kalshi column, not the coin flip.
- **Opening call** is one UP/DOWN forecast per window, made the moment Kalshi publishes the window's opening price K (usually 5–40 s in; until then the panel says it is waiting) and then frozen. If K takes more than 3 minutes, that window has no call. It starts from Model UP at the open (≈50%, since spot ≈ K) and adds a lean of at most ±10 points from BTC's 30-s and 2-min move (in σ units), top-3 Kalshi book imbalance, and 30-s Kalshi trade flow. The lean weights are an untested hypothesis. The call never feeds BUY signals. "On track / Behind now" compares live proxy to K. If the engine was not running in a window's first minute, that window has no call.
- Maker limit is fair probability minus margin, rounded down to a legal tick and below the ask. Queue ahead includes orders at the limit and better prices. The conditional edge does not account for uncalibrated adverse selection or guarantee a fill.
- The chart compares model UP with the YES midpoint. Book ladders show YES and NO bids; each opposite bid implies an ask at 1−bid. Depth can be fractional. REST fallback is explicitly labeled.
- Session P&L is realized net dollars from KXBTC15M account records, with actual fees. Trades count distinct fill order IDs. Win rate and streak use realized closing orders (partial fills grouped by order) and residual market settlements. Canonical directional fills net complementary positions; missing actual fees or unsupported records suppress account readiness. Guardrails suppress advice, not trades placed manually elsewhere.
- Daily lock persists through restarts until the next America/Los_Angeles day unless the typed override is logged. Initial-day balance is the first observed cash balance and is labeled in the event journal; exact historical midnight cash cannot be reconstructed reliably from trading records alone (deposits/transfers). Subsequent days capture the balance when first observed after midnight.
- Enable browser audio with a click, then toggle audio/notifications in Settings. Every numeric threshold and model parameter is editable and persisted. Dollars rather than cents are used in settings, so 0.04 means 4¢.

## The proof engine

SQLite WAL database: ./data/advisor.db. ticks record every active-market second, including missing inputs and the reason in context; signals deduplicate market/style/side/price; paper_trades use one contract; outcomes store official results and proxy average; real_trades retain normalized fills and settlements. account_raw and events retain reconciliation/audit evidence. Only ticks are pruned after 30 days; other data is retained forever.

Paper takers enter at observed ask plus fee. Maker simulations fill only on an opposite aggressor trade strictly through the resting price, with one contract deducted from observed volume per simulated fill. Quotes touching a limit do not count. They expire at close and settle on an official result. Public REST fallback cannot observe all trade-throughs; it will undercount maker fills. Simulations ignore exchange queue cancellations and partial execution dynamics.

Calibration uses one paired tick nearest 180s remaining (±30s) per settled market for reliability/Brier. Lower Brier is better; model minus market below zero indicates better paired forecasts in this sample. Profit curves use realized paper/real outcomes. Realized EV per filled signal has a 95% market-cluster bootstrap CI (2,000 resamples), unavailable below two independent markets. Predicted EV is the original model edge. Time, regime and edge breakdowns distinguish styles. Basis error is proxy closing average minus official numeric expiration value; it stays missing if either input is absent. Opening calls are scored separately: hit rate with a Wilson 95% CI, and Brier against a coin flip (0.25), the same call without the lean ("model only"), and the Kalshi mid at the moment of the call. Export all six tables (the five required plus opening_calls) from the calibration page.

## Historical backtest

`npm run backtest` downloads public history into `data/history.db` (resumable; re-runs only fetch what is missing) and writes [docs/BACKTEST.md](docs/BACKTEST.md). Sources: every settled KXBTC15M round with Kalshi 1-minute YES bid/ask candles (live endpoint after Kalshi's historical cutoff, `/historical/...` before it), KXBTCD hourly strikes within $1,000 of spot at each hour's open, and Coinbase BTC-USD 1-minute candles. Options: `--days 90` (15-minute history), `--hourly-days 60` (hourly; live endpoint only), `--skip-fetch` (re-analyse), `--fetch-only`. No credentials are used and nothing is sent to Kalshi but public GETs (serialised, ~7/s, with 429 backoff), so it can run alongside the app.

It replays the app's own diffusion model, fee function and quant prior blend at every 1-minute candle close and reports: Brier score versus Kalshi's mid by minutes left (round-clustered 95% ranges), whether contracts at each price win as often as their price plus fee implies, strategy results per contract after fees (the app's BUY rule with and without the exit plans, edge thresholds, favorites, longshots, first-minute entries) split into first and second half of the period, model calibration and a variance-multiplier scan, and what different stake sizes do to a $40 account. Limits: decisions are at 1-minute resolution (the final minute's locked-average edge is not testable this way), spot is Coinbase plus a learned basis rather than the 4-venue proxy, and depth/latency are not modelled. `output/backtest.json` holds the raw numbers.

## Self-updating

While the app runs it improves itself only where held-out data proves the change, and never changes trading behaviour on its own:
- **Daily backtest refresh.** Once the verdict is 24 h old, never in the first 10 minutes after start and at most one attempt an hour, the engine runs `scripts/backtest.ts` as a separate below-normal-priority process (`logs/backtest.log`, report in `output/BACKTEST.md`). It downloads only new history, re-runs the replay and the final-minute study, and rewrites `data/backtest-verdict.json`, which the engine hot-reloads; the BUY notes and the footer pick it up. It takes ~30 s.
- **Forecast blends.** The main quant blend refits after every settled round. A separate late-round blend is fitted on the final-minute seconds (nearest 50/40/30/20/10 s of every round). Each replaces the default blend only after beating it on rounds held out of the fit (≥ 60 later markets, 20 hour blocks and four expanding chronological folds); the late one then serves the last minute. The learned weights and their out-of-sample scores are logged (`quant-fit`, `late-fit`).
- **Final-minute data is kept for good.** Pruning deletes ticks older than 30 days except the final minute (~25 MB/day), so the study keeps growing.
- **Trading changes stay manual.** When the final-minute study shows ≥ 100 trades with a 95% range above zero and both halves positive, the dashboard says so. Final-minute entries (5–59 s left) are a setting, *Allow entries in the final minute*, off by default. If it is on while the study says entries lose or are unproven, the dashboard warns.
