# Decisions

1. Use dedicated production Kalshi hosts; official recommendation supersedes old elections hostname. Only fixed allowlisted HTTPS/WSS hosts receive signatures; redirects disabled. HTTP API client only implements GET. Executor is disabled and throws even if enabled in v1.
2. Fee rounding uses the current API specification over legacy cent-rounded examples. Account precision defaults to direct member 0.0001 dollars; settings allow conservative cent precision. Series and event fee metadata gate recommendations if unsupported.
3. Arithmetic settlement average uses exact Brownian integral mean/variance in price space with sigma from log returns; probability uses a moment-matched lognormal approximation. The arithmetic average of correlated lognormal prices has no closed-form lognormal law. This is a diffusion approximation, not an exact BRTI distribution. Exact locked observations and variance weights are tested.
4. No imputation across missing seconds for locked averages or opening reference; suppress when coverage is incomplete. Restore two-hour proxy history from SQLite on restart. All-four feed health required for signals by default, as requested, even if it suppresses most opportunities.
5. One orderbook_delta subscription covers both markets. Live Kalshi merges later subscribes into the first sid and numbers every message on that sid (snapshots, deltas and the ok ack) with one counter, so gaps are detected per sid, not per market (the original per-market assumption caused a reconnect storm on first live authenticated run). REST cannot reseed the WS sequence; on a gap invalidate and reconnect while using independent REST fallback.
6. Paper signals deduplicated per market/side/type and price to avoid one-second pseudo-replication. Maker paper orders expire at close; only opposite aggressor trades strictly through a resting price can fill, never quote touches. Results are conservative simulations, with adverse-selection uncertainty.
7. Guardrails use local calendar day America/Los_Angeles and realized net account cashflows with actual fees, not hypothetical paper outcomes. Missing authenticated account history suppresses sizing and taker signals.
8. Initial-day loss baseline is first observed cash balance; reconstructing midnight cash from trades alone omits deposits/transfers. Persist the baseline and daily lock. The UI and README disclose this limitation; exact historical midnight balances need an account statement.
9. Upgrade Vitest and Tailwind to current patched free versions; override vulnerable transitive PostCSS/shell-quote. Retain requested Next.js 15.5.27. The final dependency audit must be clean. Node direct --import tsx avoids Windows supervisor orphaning a tsx CLI child.
10. Persist one fixed-horizon paired forecast inside every outcome so calibration survives tick pruning. Bootstrap by market, not individual tick/signal; fewer than two markets cannot supply an independence-aware CI. All raw signal contexts and real account records remain exportable.
11. Opt into unified YES-leg WS pricing explicitly, then normalize NO-leg bids internally. Fill direction comes from outcome_side/book_side (yes = buy YES or sell NO); every fill is a purchase in that direction netted FIFO against the complementary side. Live-verified 2026-10-07 on 480 account fills: the deprecated side field mirrors outcome_side, so action=sell side=no means selling YES. action/side are interpreted the legacy way (side = leg traded) only when canonical fields are absent. Loss streaks include realized closing fills, grouped across partial fills, plus residual settlements.
12. Support both Ed25519 and RSA Kalshi keys (docs now recommend Ed25519). Signature scheme is chosen from the parsed key type, not the PEM header, since PKCS#8 headers are identical for both.
13. Opening call (user request): a separate, display-and-score-only forecast, one per window, frozen at the first tick of its first minute with a model ready and confirmed K. Base is the diffusion model at the open; the lean is a fixed, capped (±10pp) continuation hypothesis from logged microstructure features, because no calibration data exists yet to fit weights. It never gates or sizes trades. It is scored against a coin flip, the lean-free model and the Kalshi mid, so the user can see whether it carries information before promoting it into signals.
14. Exit advisor (user request): hold vs sell is an expected-value comparison under the model (hold = P(win); sell = bid − taker fee) with a 2¢/contract hysteresis margin so tiny model wiggles do not flip advice. Display-only; never places orders.
15. Latency (user request): evaluation/publish raised from 1 Hz to 4 Hz while journaling stays 1 Hz (calibration still uses one-second ticks). SQLite synchronous=NORMAL (safe under WAL; at most the last transaction can be lost on power failure), parsed real-trade history cached until the next account sync, and the chart memoized to redraw only when a new second is added.
16. Feed health (measured 2026-10-07): with 'quote younger than 2 s', Gemini was stale 11% of the time and all four were fresh only 85.7%, because venues push only on change. Health now separates link liveness (any frame or pong within staleMs, pings every 1 s) from quote age (≤15 s). A dead link is still caught within ~2 s; the all-four-healthy signal gate is unchanged.
17. Live call (user request): opening-call formula on current data with ±2-point direction hysteresis; clip widened to 1–99% to match the model. Gated by a data-quality check. Scored at fixed horizons (10/5/2/1 min) once per window so evidence is independent per market. Display-only.
18. UI: night-ops instrument panel (Barlow Condensed for calls, IBM Plex Sans UI, JetBrains Mono tabular data; semantic color tokens; color always paired with text/icons). Panels collapse on phones so the signal and calls are on the first screen. Fonts self-hosted by next/font at build time.
19. Sounds (user request): Web Audio synthesis instead of audio files (no assets, instant, works offline). Transition detection is a pure tested function; the first snapshot is a silent baseline. Prefs live in localStorage because they are per-device conveniences. config.audio is retained for compatibility but superseded by the sound panel.
20. Launcher: probes 127.0.0.1 (Windows resolves localhost to ::1 first while the server binds IPv4) and refuses to start a second instance while one is building.
21. Signal vs size (user-approved): sizing below one contract no longer suppresses the taker signal by default. Otherwise a small balance starved the paper-taker evidence entirely (0 recorded trades at a $5 balance). Size remains a gate for the contract count, never for edge/timing; the strict behaviour is one setting away.
22. Data review (30 settled windows, 2026-10-07): opening calls 12/20 (Brier 0.243 ≈ coin flip 0.25); the fixed momentum lean slightly hurt (0.2432 vs 0.2414 without); the Kalshi mid beat the raw model at every live horizon; proxy ran $3.16 below official BRTI. Conclusions drive 23–26.
23. Quant stack replaces the hand-set lean: Bayesian logistic blend of model, Kalshi and features with a confidence parameter held near 1 (shrinking all forecasts toward 50% hurt out of sample) and a Kalshi-shift parameter; learned weights adopted only when they beat the default blend leave-one-market-out by 0.002 Brier with ≥ 30 markets. On 20 markets the default blend (0.1865) beat the raw model (0.1912) and the fitted weights (0.1939), so the default is active.
24. Auto basis: −median of the last 30 settlement basis errors, shrunk by n/(n+5); estimated K uses the same correction.
25. Final-minute blackout (5 of 28 windows): a single skipped second made the locked average incomplete and nulled the model until close. Gaps ≤ 5 s are bridged by linear interpolation (cents of error vs a σ-of-average of tens of dollars). Root causes removed: fill warnings recomputed ~400 fills every 30 s (~300 ms stall) now cached and queried with json_extract; a > 5 s stall was treated as sleep/wake and restarted every feed — threshold raised to 15 s, shorter stalls logged.
26. Opening call made at the first second of the window using an estimated K (proxy average of the same 60 s + basis) when Kalshi's floor_strike is not yet published; markets refresh every second until it is. Previously the call waited 6–36 s for floor_strike.
27. Timing gate has a 'waiting' state before the entry window and in the final minute; it still blocks entries (the rule is unchanged) but is not shown or counted as a failure.
28. Analytics page fetches /api/engine/analytics once a minute: it is historical, so it is not pushed over the live WebSocket 3×/s.
29. Market discovery queries markets closing within the next hour (min_close_ts/max_close_ts) instead of status=open + status=unopened. Verified live 2026-10-07: status=unopened returns the furthest-future markets first (a day ahead, paginated), so the next round was often absent; at 16:30 the app had no current market for 3 s and its 'next' market was 21:15. Known markets are also kept until they close.
