# Kalshi verification — 2026-10-06

Verified against current official documentation and live public KXBTC15M series/market responses. Account verification remains pending local credentials.

- Recommended production REST: `https://external-api.kalshi.com/trade-api/v2`; WS: `wss://external-api-ws.kalshi.com/trade-api/ws/v2`. Older elections hosts remain supported. [Environments](https://docs.kalshi.com/getting_started/api_environments)
- Key types: Ed25519 (Kalshi-recommended; signs the pre-sign text directly) or RSA-PSS SHA256 with digest-length salt (32 bytes). Both PEMs may start `-----BEGIN PRIVATE KEY-----`; the engine detects type from the key. [API keys](https://docs.kalshi.com/getting_started/api_keys) Sign timestamp in milliseconds + uppercase method + full path, excluding query. Headers: KALSHI-ACCESS-KEY, KALSHI-ACCESS-SIGNATURE (base64), KALSHI-ACCESS-TIMESTAMP. [Authentication](https://docs.kalshi.com/getting_started/quick_start_authenticated_requests)
- GET `/markets?series_ticker=KXBTC15M&status=open`, `/markets/{ticker}`, `/markets/{ticker}/orderbook`, `/series/KXBTC15M`, `/portfolio/balance`, `/portfolio/positions`, `/portfolio/fills`, `/portfolio/settlements`. Cursor pagination is mandatory; old records move to `/historical/fills` and `/historical/positions`. [Markets](https://docs.kalshi.com/api-reference/market/get-markets), [Balance](https://docs.kalshi.com/api-reference/portfolio/get-balance), [Positions](https://docs.kalshi.com/api-reference/portfolio/get-positions), [Fills](https://docs.kalshi.com/api-reference/portfolio/get-fills), [Settlements](https://docs.kalshi.com/api-reference/portfolio/get-settlements).
- WS channels `orderbook_delta`, `ticker`, `trade`, `fill` available. Authentication required on connection. Book snapshot `yes_dollars_fp`/`no_dollars_fp`; delta `price_dollars`, `delta_fp`, `side`. Sequence is scoped to subscription ID, not market. Live-verified 2026-10-07: a second orderbook_delta subscribe merges into the existing sid (ok ack with seq 2), and both markets share that sid's counter; the engine uses one subscription for both markets and checks gaps per sid. Explicit `use_yes_price:true` opts into unified YES-leg prices; normalize NO prices as 1−price internally. REST `orderbook_fp.yes_dollars`/`no_dollars` remain separate-leg bids; YES ask = 1 − NO bid. REST has no compatible WS sequence: recovery reconnects for a fresh WS snapshot while REST supplies independent fallback. [Book](https://docs.kalshi.com/websockets/orderbook-updates), [Ticker](https://docs.kalshi.com/websockets/market-ticker), [Trades](https://docs.kalshi.com/websockets/public-trades), [Fills](https://docs.kalshi.com/websockets/user-fills).
- Live market fields: `floor_strike` confirmed opening reference; `open_time`, `close_time`, `status` (response `active`, query `open`), `result` (`yes`/`no`), `expiration_value`. Dollar strings `yes_bid_dollars`, `yes_ask_dollars`, `no_bid_dollars`, `no_ask_dollars`; quantities `*_fp` may be fractional. Current `price_ranges` include 0.001 dollar ticks near tails and 0.01 in the middle. Never assume cent ticks. [Fixed point](https://docs.kalshi.com/getting_started/fixed_point_migration), [Market](https://docs.kalshi.com/api-reference/market/get-market).
- Live `rules_primary` confirms YES when closing sixty-second BRTI average >= opening sixty-second average; secondary rules round closing average to two decimals. A venue median is an estimated proxy, not licensed BRTI; locked observations remain proxy estimates. [Series](https://external-api.kalshi.com/trade-api/v2/series/KXBTC15M).
- Current schedule effective July 7, 2026: taker model = 0.07 × multiplier × C × P × (1−P); maker = 0.0175 × maker multiplier × C × P × (1−P). KXBTC15M public series is `quadratic`, multiplier 1, implying taker-only fees; `quadratic_with_maker_fees` enables maker fees. Event overrides take priority. Schedule prose now rounds cost + fee to centicent for direct members; its illustrative table still shows cents. Implement current API rounding: model ceil to six decimals, then cost + fee aligned to account precision; default direct 0.0001 dollars, configurable 0.01 for non-direct. Real fees are read from fills. [Official fee schedule](https://kalshi.com/docs/kalshi-fee-schedule.pdf), [Rounding](https://docs.kalshi.com/getting_started/fee_rounding), [Event overrides](https://docs.kalshi.com/api-reference/events/get-event-fee-changes).
- Rate limits now token buckets, default GET cost 10 tokens. Basic 200 read tokens/s (about 20 default reads/s); Advanced 300. Query `/account/limits` for actual tier and `/account/endpoint_costs` for special costs; not verifiable without key. Use conservative serial requests, exponential 429 backoff; no assumed Retry-After. [Limits](https://docs.kalshi.com/getting_started/rate_limits), [Account](https://docs.kalshi.com/api-reference/account/get-account-api-limits).

Feed references: [Coinbase](https://docs.cdp.coinbase.com/exchange/websocket-feed/channels), [Kraken](https://docs.kraken.com/api/docs/websocket-v2/ticker), [Bitstamp](https://www.bitstamp.net/websocket/v2/), [Gemini](https://developer.gemini.com/websocket/streams). Kraken v2 uses BTC/USD, replacing XBT/USD. Feed transport latency is displayed separately from quote age; feeds without timestamps show lag unavailable.

Final protocol review: canonical `outcome_side=yes` / `book_side=bid` means long YES (buy YES or sell NO); NO/ask means long NO (buy NO or sell YES). These fields cannot be combined naively with deprecated `action`/`side`. Use consistent legacy pairs when available; otherwise treat directional fills as purchases with complementary-side netting. Partial closures realize FIFO profit and feed streak guards. [Order direction](https://docs.kalshi.com/getting_started/order_direction). Get Event does not include effective fee fields: poll and paginate `/events/fee_changes`, applying the latest effective override for the event over the current series schedule; future scheduled changes wait until effective time. The live fee-change response contained 53 records and no KXBTC15M override during verification.
